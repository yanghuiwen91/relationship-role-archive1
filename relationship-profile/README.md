# 关系角色档案

移动端优先的中文关系趣味测试。Node.js 24 + 内置 SQLite + 原生 ES Modules，无第三方运行依赖。

## 快速运行

```sh
cd relationship-profile
node --version # 需要 Node.js 24 或更新版本
npm run setup  # 生成随机后台密码与访问码 pepper，保存到本机 .env
npm start
```

打开 http://127.0.0.1:3100 。后台 http://127.0.0.1:3100/admin ，管理密码是本机 `.env` 中的 `ADMIN_PASSWORD`。不要向买家发送管理密码。项目无需 `npm install`。

若跳过 `setup`，只开启独立演示，正式访问码接口和后台返回明确的未配置提示。生产模式缺少密钥直接拒绝启动。演示答案保存在当前浏览器会话，不占用正式次数，不进入正式数据库。

## 已实现

- 服务端校验随机访问码、错误状态、限流、批量生成、停用/恢复、到期日、次数和使用记录。
- 24道原创情境题、上一题/下一题、选项修改、刷新恢复、服务器持久化进度。
- 八维均衡权重、理论归一化、八种多维原型、确定性平分规则、接近提示。
- 九模块报告：实际选择依据、八维条形图、场景化付出、需求、误会、28种双角色组合、小练习、表达卡。
- Canvas 真实 PNG（1080×1560）分享卡，图片预览、下载链接与长按提示，不声称设备已保存。
- 同一访问码可查看以往报告；开始新测试扣次，完成与复看不再扣次。

## 访问规则

1. 开始时以 SQLite 事务扣1次，生成服务端测试记录。请求 key 对访问码唯一；同一码最多有一个进行中的测试。
2. 网络重试复用 key；不同 key 遇到进行中的测试也恢复同一份，不重复扣次。提交已完成测试只返回原报告。
3. 已开始测试即使后来到期也能继续；到期/次数用尽禁止新测试，但允许登录恢复和复看。若没有已有档案，则验证页直接提示到期/耗尽。
4. 停用会阻止新登录，也立即阻止已有会话读写。恢复后可重新使用。
5. 翻页保存到服务端；刚选中尚未翻页的答案存于当前标签会话草稿。多页面冲突使用 revision 检测，明确要求刷新，避免静默覆盖。刷新后从“继续上次探索”恢复。
6. 正式报告与答案不会放在 URL 或常规日志。前端不含有效码列表。后台列表仅提供使用次数、状态、批次和开始/完成事件。

## 文件结构

- `server.mjs`：HTTP/API、SQLite schema、事务、权限和限流。
- `config/questions.json`：24题及每选项权重。
- `config/scoring.json`：维度、原型、接近阈值和规则版本。
- `config/roles.json`：八种角色原型文案、练习和表达句。
- `config/report.json`：28种角色组合的差异化解释。
- `public/scoring.mjs`：浏览器演示与服务端共用的确定性计分函数。
- `public/app.mjs` / `style.css`：界面、后台与图片导出。
- `build-demo.mjs`：从配置生成独立静态演示，不连接正式数据库。
- `tests/`：计分与真实 HTTP/SQLite 集成测试。
- `SCORING.md`、`DEPLOYMENT.md`、`DELIVERY.md`、`QA.md`：计分、部署、交付和验收说明。

正式服务 `/content.json` 直接从 config 生成响应，修改 config 并重启即可更新；静态演示使用 `node build-demo.mjs` 重新构建。配置升级应发布新测试版本并保留旧配置，不要在已有付费测试运行中直接更换题意或计分规则。当前产品只有一个测试版本；跨版本配置选择需要在扩展时实现。
