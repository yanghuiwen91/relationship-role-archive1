# 部署说明

## 完整后端部署

需要你提供或选定：带持久磁盘的服务器/容器平台、正式域名、DNS权限和HTTPS证书配置。无需第三方AI API，也无需付费数据库。当前未连接任何正式支付或发货账号。

1. 安装 Node.js 24+，上传项目源码。以独立非root账号运行，工作目录固定在项目目录。
2. 执行 `npm run setup` 生成随机 `.env`。保持 `CODE_PEPPER` 不变，丢失/更换会使已有访问码及会话不可验证。
3. 在部署环境将 `NODE_ENV` 设为 `production`；`HOST=127.0.0.1`、`PORT=3100`，`DB_PATH` 指向受保护的持久目录（如 `/var/lib/relationship/archive.sqlite`）。容器需要挂载持久卷。不要放在静态资源目录。
4. 用 systemd/容器重启策略托管 `node server.mjs`。项目无需安装依赖，无构建步骤。
5. 配置同域HTTPS反向代理，保留原始Host；生产Cookie为 Secure/HttpOnly/SameSite=Strict。不要直接用HTTP测试生产登录。
6. 打开正式域名 `/admin`，使用服务器环境变量中的管理密码登录。生成测试码，在新浏览器会话完成一次全流程后，再生成交付批次。购买者只需正式网址和自己的访问码。

Nginx代理片段（证书按托管平台配置）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3100;
    proxy_set_header Host $host;
    client_max_body_size 12k;
}
```

本项目不盲目信任客户端的 `X-Forwarded-For`。内置限流基于真实socket地址：直连时按客户IP，反向代理时可能按代理出口聚合。正式流量应在可信代理/边缘层对 `/api/verify` 和 `/api/admin/login` 配置客户端IP限流，同时避免因单一代理地址导致多人失败尝试共享内置额度。当前内置限制为验证失败12次/15分钟、后台失败5次/15分钟，验证成功会重置对应计数；不要通过任意转发头绕开保护。

## 数据与运维

SQLite WAL 适合单实例运行。不要让多个独立容器各自使用本地库，也不要把此方案原样部署到临时文件系统的无服务器函数。扩展多实例应迁移共享数据库并保留事务、幂等键和唯一活动测试约束。

只保存访问码哈希（随机96bit访问码+服务端pepper）、批次标签、有效期、额度、测试答案、报告和使用事件。管理端默认没有读取答案接口。测试答案没有放进URL；应用不记录请求体或访问码。反向代理也不要记录POST请求体。

定期备份SQLite（使用SQLite在线backup或停服备份，不能只复制运行中的主文件而忽略WAL）。同时安全备份pepper。限制数据库和 `.env` 的访问权限。当前没有自助删除或自动保留期清理，运营方应按自身保留政策实施备份与到期清理；不要在批次备注中存储订单/身份信息。

后台为单管理员密码方案，支持退出；没有多管理员账号、MFA或审计导出。可额外在网关对 `/admin` 和 `/api/admin/*` 设置访问限制。密码修改后应清理管理员session记录，旧会话最多4小时有效；访问码用户会话30天。

## 静态演示

运行 `node build-demo.mjs`，`dist/` 为可托管的演示资源。配置明确写有 `demoOnly:true`，不调用正式验证、后台或数据库。演示进度仅在当前浏览器会话保存。

本次 Sites 发布为账号私有演示，不能作为小红书购买者正式交付地址。正式后端源码已完成，但未在 Sites 上配置Node/SQLite运行环境。请按以上方式部署完整服务后使用自己的正式域名。
